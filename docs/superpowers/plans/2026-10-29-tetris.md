# Tetris Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add classic Tetris (a 10×18 field, 7 coloured shapes, a next-piece preview, points, levels and a best score) as the second game in Home → Retro games.

**Architecture:**
- Plain rule functions (`tetris*`) take a state and return a new state, with no React or DOM inside. They are exposed as `window.__oneTetris`.
- A `TetrisGame` React component owns every timer (gravity, lock delay, the line-clear flash, held-key repeat) and draws a CSS grid of squares, the same way `SnakeGame` does.
- It reuses `GamesPanel`, `useGameRecord` and `retroSound`.

**Tech Stack:** the existing single-file React 18 app in `index.html` (no build step); tests use `node:test` + Playwright through `tests/helpers.cjs`.

**Spec:** `docs/superpowers/specs/2026-10-29-tetris-design.md`

## Global Constraints

- All code lives in `index.html`, right after the Snake code (`SnakeGame`) and before `const GAMES`. Write `React2.createElement` calls in the same style as Snake. No new dependencies.
- The field is 10 wide × 18 tall. `field[y][x]` is `null` or a shape id. y = 0 is the top row. Cells above the top (y < 0) and outside the walls count as blocked.
- Colours are fixed: I white, O yellow, T pink, S green, Z red, J blue, L orange. Grey is only the landing shadow.
- Gravity: `max(80, 800 − (level − 1) × 70)` ms. Lock delay 500 ms, restarted by at most 15 successful moves or turns per piece. Line flash 250 ms (0 with reduced motion).
- Points: 1/2/3/4 lines = 100/300/500/800 × the level before the clear. Soft drop +1 per row, hard drop +2 per row. Level = 1 + floor(lines / 10).
- Held-key repeat: first repeat after 170 ms, then every 50 ms.
- The best score is saved with `useGameRecord("tetris")` in `localStorage["one.games.v1"]`.
- Copy fixed by the spec:
  - names: "Tetris", "Next", "Score", "Lines", "Level", "Best", "Ready?", "Play", "Paused", "Resume", "Game over", "Play again", "🏆 New record!", "TETRIS!", "Game sounds".

## Review Focus

1. **Key mashing during the 250 ms line-clear flash:** moves, turns and drops are ignored while `state.clearing` is non-empty, so no second lock and no double score. *(Task 2 test)*
2. **Hard drop during the lock delay:** it locks once and scores once, and the pending lock timer does nothing afterwards. *(Task 3 test)*
3. **A turn at the top row:** a kick that would push cells above y = 0 is refused or picks another kick, and never throws. *(Task 1 test)*
4. **A held arrow when the window loses focus or the game pauses:** the repeat stops and does not start again on its own after resume. *(Task 3 test)*
5. **Space while the Play button has focus:** it starts exactly one game, not one from keydown plus one from the button's click. *(Task 3 test)*

### Task 2: Gravity, locking, line clears, scoring, levels, game over

**Files:**
- Modify: `index.html` (Tetris rules block)
- Test: `tests/tetris.test.cjs`

**Interfaces:**
- Consumes: Task 1.
- Produces:
  - `tetrisTick(state) -> State`: moves the piece down 1 row, with `grounded: false`. If it can't fall, returns the same piece with `grounded: true`.
  - `tetrisSoftDrop(state) -> State`: same as tick, plus +1 score when it moved.
  - `tetrisHardDrop(state) -> State`: moves to the ghost position, +2 per row, then `tetrisLock`.
  - `tetrisLock(state) -> State`: writes the cells into `field`. Sets `clearing` to the full row indexes (ascending). If `clearing` is empty, it spawns next at once.
  - `tetrisClear(state) -> State`: removes the `clearing` rows, drops the rows above, scores, updates lines/level, sets `clearing: []`, spawns next.
  - `tetrisSpawn(state) -> State` (internal but exported): next → piece, draws a new next from the bag, `lockMoves: 0`, `grounded: false`. If the new piece doesn't fit, `status: "over"`.
  - `tetrisGravity(level) -> ms`.
  - `TETRIS_POINTS = [0, 100, 300, 500, 800]`.
  - A clear also sets `last: { lines: n, points, levelUp: boolean, at: counter }` so the UI can play sounds and the "TETRIS!" burst.

- [ ] **Step 1: Write the failing tests.**
  - `gravity speeds up and stops at 80 ms`: `tetrisGravity(1) === 800`, `tetrisGravity(10) === 170`, `tetrisGravity(11) === 80`, `tetrisGravity(40) === 80`.
  - `tick falls, then reports grounded`: after 16 ticks an O on an empty field has its lowest cell at y = 17. The 17th tick returns `grounded: true` and the same y.
  - `hard drop lands on the ghost and scores 2 per row`: from spawn, the T's ghost y equals its locked y, and the score is `2 × rows fallen`. The field now holds 4 `"T"` cells.
  - `clearing 1–4 lines scores 100/300/500/800 × level and drops rows above`:
    1. Build a field with n full rows at the bottom (missing only column 0) and a marker block at (5, 17 − n).
    2. Drop a vertical I into column 0, then call `tetrisClear`.
    3. Check the score: 100, 300, 500 or 800 at level 1. For n = 4 at level 3 it is 2400.
    4. Check that the marker is now at (5, 17).
  - `level rises every 10 lines using the old level for points`: with `lines: 9, level: 1`, clearing 1 line gives `lines: 10, level: 2`, +100 points (not 200), and `last.levelUp === true`.
  - `blocked spawn ends the game`: fill rows 0–1 in columns 3–6, then `tetrisSpawn` gives `status: "over"`.
  - `input is ignored during the clear flash` (Review Focus 1): while `clearing.length > 0`, move, rotate, soft drop, hard drop and tick all return the same object (`===`).
