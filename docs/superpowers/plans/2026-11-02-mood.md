# Mood Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mark each day with one of 5 faces and a note, and see the week's mood, best day and worst day on a new Mood page, with a "How was today?" card on Home.

**Architecture:** A new synced `moods` collection in the workspace. Pure week and summary maths in `pages/mood/rules.js` (Node-testable, like `pages/telegram/rules.js`). Shared pieces (mood words, the `MoodFace` SVG and the `useMoodDay` hook that applies the marking rules) live in `index.html` and are handed to pages through `window.__oneApp`. The page is `pages/mood/mood.js` and `mood.css`, loaded like every other page; Home gets a card in `pages/home/home.js`.

**Tech Stack:** React 18 UMD with `React2.createElement` (no JSX, no build step), plain CSS, Node's built-in test runner with Playwright Chromium (`tests/helpers.cjs`).

**Spec:** `docs/superpowers/specs/2026-11-02-mood-design.md`

## Global Constraints

- Moods: 1 awful, 2 bad, 3 okay, 4 good, 5 great. Words shown capitalised: "Awful", "Bad", "Okay", "Good", "Great".
- One entry per local date (`YYYY-MM-DD`): `{ id, date, mood, note, createdAt }`; `mood` is 1–5 or `null` (a note with no face); `note` at most 500 characters.
- Weeks run Monday to Sunday.
- Today and past days can be marked; future days cannot.
- Week's mood: average of marked days, rounded to nearest face, x.5 rounds up; shown as "Good · 5 of 7 days"; no marked days → "No days marked yet".
- Best/worst: highest/lowest mood; ties → day with a non-blank note, then the more recent day. Shown only with ≥2 marked days that are not all the same; else "Mark a few more days to see your best and worst."
- No notifications. Home card gets a stronger accent border from 21:00 while today is unmarked.
- Internal names keep `one` (`window.__oneMoodRules`, `one.workspace.v1`); user-facing name is Core.
- Pages are a bottom dock, not a side menu: Mood is a 7th dock tab placed after Tasks.
- Faces are SVG, never emoji; the word is always visible or the accessible name; colour is never the only clue.
- No sideways scroll from 375px wide; works in light and dark themes.
- Code style: match the surrounding files (`React2.createElement` as `h`, double quotes, 2-space indent, comments in plain sentences).

## Review Focus

1. **Midnight while Core is open:** after the clock passes midnight, the Home card asks about the new day (unmarked) instead of showing yesterday's face. Test in Task 3.
2. **Same day marked on two devices before they sync:** two entries with the same `date` and different ids; the page shows one per day (the most recently changed, by `_m` then `createdAt`) and the summary counts that date once. Test in Task 1 (`latestByDate`).
3. **A note of only spaces:** counts as no note for tie-breaking and is not listed under the week's notes. Test in Task 1.
4. **Weeks across a month, a year and a clock change:** `weekStart` and `weekDays` give the right seven dates (e.g. Mon 2026-12-28 to Sun 2027-01-03; the week of 2026-03-29). Test in Task 1.
5. **A 500-character note with no spaces on a phone:** wraps inside its card, no sideways scroll at 375px. Test in Task 4.

### Task 1: Week and summary rules

**Files:**
- Create: `pages/mood/rules.js`
- Test: `tests/mood-rules.test.cjs`

**Interfaces:**
- Produces (`module.exports` in Node, `window.__oneMoodRules` in the browser; same wrapper as `pages/telegram/rules.js`):
  - `weekStart(iso: string) -> string` — the Monday on or before `iso`.
  - `weekDays(startIso: string) -> string[7]` — Monday..Sunday.
  - `shiftWeek(startIso: string, n: number) -> string` — the Monday `n` weeks later (negative for earlier).
  - `canMark(iso: string, today: string) -> boolean` — `iso <= today`.
  - `hasNote(entry) -> boolean` — `note` is a string with non-blank text.
  - `latestByDate(entries) -> Map<string, entry>` — one entry per date, keeping the greatest `_m` (number, missing = 0), then the greatest `createdAt`.
  - `summarize(entries, startIso: string) -> { marked: number, average: 1..5 | null, best: entry | null, worst: entry | null, notes: entry[] }` — uses only that week's dates via `latestByDate`; `marked` counts entries with a `mood`; `notes` are the week's entries with `hasNote`, newest date first.
- Date maths must not depend on the local time zone: parse `YYYY-MM-DD` with `Date.UTC` and read back with `getUTC*`.

- [ ] **Step 1: Write the failing tests** in `tests/mood-rules.test.cjs`, requiring `../pages/mood/rules.js`. Use `e(date, mood, note = "", extra = {})` → `{ id: date + mood, date, mood, note, createdAt: "2026-11-01T00:00:00Z", ...extra }`.

```js
test("weeks run Monday to Sunday, across months, years and clock changes", () => {
  assert.equal(weekStart("2026-11-02"), "2026-11-02"); // Monday
  assert.equal(weekStart("2026-11-08"), "2026-11-02"); // Sunday
  assert.equal(weekStart("2027-01-01"), "2026-12-28");
  assert.deepEqual(weekDays("2026-12-28"), ["2026-12-28","2026-12-29","2026-12-30","2026-12-31","2027-01-01","2027-01-02","2027-01-03"]);
  assert.deepEqual(weekDays("2026-03-23").slice(5), ["2026-03-28", "2026-03-29"]);
  assert.equal(weekStart("2026-03-29"), "2026-03-23");
  assert.equal(shiftWeek("2026-11-02", -1), "2026-10-26");
  assert.equal(shiftWeek("2026-12-28", 1), "2027-01-04");
});
test("today and past days can be marked, future days cannot", () => {
  assert.equal(canMark("2026-11-02", "2026-11-02"), true);
  assert.equal(canMark("2026-11-01", "2026-11-02"), true);
  assert.equal(canMark("2026-11-03", "2026-11-02"), false);
});
test("the week's mood is the rounded average of marked days", () => {
  const s = summarize([e("2026-11-02", 4), e("2026-11-03", 3), e("2026-11-04", null, "just a note")], "2026-11-02");
  assert.equal(s.marked, 2);
  assert.equal(s.average, 4); // 3.5 rounds up
  assert.equal(summarize([e("2026-11-02", 2), e("2026-11-03", 3), e("2026-11-04", 3)], "2026-11-02").average, 3); // 2.67
  assert.equal(summarize([], "2026-11-02").average, null);
  assert.equal(summarize([e("2026-10-30", 5)], "2026-11-02").marked, 0); // other week
});
test("best and worst: ties go to a day with a note, then the later day", () => {
  const s = summarize([e("2026-11-02", 5, "run"), e("2026-11-04", 5), e("2026-11-03", 1), e("2026-11-05", 1)], "2026-11-02");
  assert.equal(s.best.date, "2026-11-02");
  assert.equal(s.worst.date, "2026-11-05");
});
test("a note of only spaces is no note", () => {
  const s = summarize([e("2026-11-02", 5, "   "), e("2026-11-03", 5), e("2026-11-04", 2)], "2026-11-02");
  assert.equal(s.best.date, "2026-11-03");
  assert.deepEqual(s.notes, []);
  assert.equal(hasNote({ note: " \n " }), false);
});
test("best and worst need two marked days that differ", () => {
  assert.equal(summarize([e("2026-11-02", 4)], "2026-11-02").best, null);
  const same = summarize([e("2026-11-02", 3), e("2026-11-03", 3)], "2026-11-02");
  assert.equal(same.best, null);
  assert.equal(same.worst, null);
});
test("one entry per day when two devices marked the same day", () => {
  const a = e("2026-11-02", 2, "", { id: "a", _m: 100 });
  const b = e("2026-11-02", 5, "", { id: "b", _m: 200 });
  assert.equal(latestByDate([a, b]).get("2026-11-02").id, "b");
  const s = summarize([a, b, e("2026-11-03", 3)], "2026-11-02");
  assert.equal(s.marked, 2);
  assert.equal(s.best.id, "b");
});
test("the week's notes, newest first", () => {
  const s = summarize([e("2026-11-02", 4, "a"), e("2026-11-04", null, "c"), e("2026-11-03", 2, "b")], "2026-11-02");
  assert.deepEqual(s.notes.map((x) => x.note), ["c", "b", "a"]);
});
```

    - `setMood(n)`: no entry → `add("moods", { id: newId(), date, mood: n, note: "", createdAt })`; `entry.mood === n` → `remove` if the note is blank, else `update` with `mood: null`; otherwise `update` with `mood: n`.

- Sample data: `moods` for `addDays(today, -1)` (4, "Long walk after work, felt clear."), `-2` (2, "Slept badly, too many meetings."), `-3` (5, "Finished the portfolio intro!"), each with `sample: true`.
