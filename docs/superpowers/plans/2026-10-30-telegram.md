# Telegram in ONE Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Connect the owner's own Telegram account to ONE so they see who is waiting in their chosen private chats, in priority order, and can read and reply from ONE.

**Architecture:**
- GramJS runs in the browser from a pinned, pre-bundled file, and only `pages/telegram/client.js` touches it.
- A plain-JS service (`pages/telegram/service.js`) holds the live Telegram state and publishes it. The core (`index.html`) loads that service in the background when this device has a Telegram login, and exposes a `useTelegram()` hook.
- The Home card, the dock badge and the Telegram page all read from that hook.
- The priority rules are pure functions in `pages/telegram/rules.js`, tested in Node.

**Tech Stack:** React 18 UMD (no build step), GramJS (npm `telegram` 2.26.22) bundled once with esbuild 0.24.0, Playwright tests with `node --test`.

**Spec:** `docs/superpowers/specs/2026-10-29-telegram-design.md`

## Global Constraints

- No build step for the app; the GramJS bundle is a committed file, `pages/telegram/gramjs-2.26.22.js`. The version in its name means a saved copy never goes stale.
- Private chats with people only: no bots, deleted accounts, Saved Messages, groups or channels.
- No server; the session string and the app key (`api_id`, `api_hash`) are kept only in `localStorage["one.telegram.device.v1"]` on this device. They are never synced and never committed.
- Synced preferences live in `settings.telegram = { chats: { [userId]: { level: "high" | "normal" | "low", name, handled?: messageId } }, limits: { normal: 180, low: 720 } }` (minutes).
  - Decision: inside `settings`, because settings already sync, newest wins.
- Moving up: a chat moves up one level each time it waits past its current level's limit. With the defaults, Low becomes Normal at 12 h and High at 15 h; Normal becomes High at 3 h; High never moves.
- Order: higher current level first, then the longest wait.
- While ONE is locked, nothing from Telegram shows. This holds by construction: the lock unmounts the app, and the service stops.
- Copy is fixed by the spec:
  - *"You have messages from …"*, *"Answer X first: waiting 5 h."*, *"waiting 13 h, moved up from Low"*
  - *"All caught up on Telegram."*, *"Telegram isn't reachable right now."*
  - *"That code didn't work. Send a new one?"*, *"That password didn't work. Try again."*
  - *"Telegram asks you to wait N minutes before trying again."*, *"Reconnecting…"*, *"You were logged out of Telegram."*
  - *"N new chats in Telegram"*, *"No reply needed"*, *"Next: <name>"*, *"Open in Telegram"*
- Every page file loads like the others: added to `PAGE_IDS` (loader and `<head>` preload), `sw.js` `SHELL`, `updateApp`'s `APP_FILES`, and the tests' page lists.
- Decision: the message cache is in memory for the session. Only the last waiting list is saved on the device (`one.telegram.cache.v1`), for the offline Home card. This narrows the spec's IndexedDB cache: YAGNI until it's slow.

## Review Focus

Most likely first:
1. **A message arriving while the chat is open.** It should appear at once, and the chat should stop counting as waiting only once the owner replies.
2. **The owner replies from their phone.** The chat should leave the waiting list when the outgoing message arrives as an update, not only for replies sent from ONE.
3. **Clock and limit edges.** Exactly at 3 h / 12 h / 15 h, the chat moves up (`>=`), and limits edited in Settings take effect at once.
4. **A chat with no messages at all, or only the owner's messages.** It should never be waiting and never crash.
5. **The device login being cleared or revoked elsewhere.** The *"You were logged out of Telegram."* state appears, and Connect works again without a reload.

Each of these has a test in the task that owns it (marked **RF1** to **RF5**).

### Task 2: Priority rules

**Files:**
- Create: `pages/telegram/rules.js`
- Test: `tests/telegram-rules.test.cjs` (Node only)

**Interfaces:**
- Produces, as `window.__oneTelegramRules` in the browser and `module.exports` in Node:
  - `DEFAULT_LIMITS = { normal: 180, low: 720 }` (minutes)
  - `waitingSince(messages: Message[], handled?: number) -> number | null`: messages are ascending by id; returns the `date` (ms) of the first incoming message after the last outgoing one whose id is greater than `handled`, or `null`.
  - `currentLevel(level, waitedMs, limits) -> { level, movedFrom: string | null }`
  - `waitingOrder(chats: { id, name, level, since: number | null }[], now: number, limits) -> { id, name, level, current, waitedMs, movedFrom }[]`: only the waiting ones, sorted.
  - `formatWait(ms) -> string`: `"2 min"`, `"5 h"` (whole hours from 1 h), `"2 days"` (from 48 h), `"1 day"`.
  - `LEVELS = ["high", "normal", "low"]` and `LEVEL_LABEL = { high: "High", normal: "Normal", low: "Low" }`
- Message shape (shared by every later task): `{ id: number, chatId: string, out: boolean, date: number (ms), text: string, replyToId: number | null, media: null | { kind: "photo" | "file" | "sticker" | "voice" | "video" | "other", name?: string, size?: number } }`

- [ ] **Step 1: Write the failing tests:**
  - `waitingSince`:
    - `[]` → `null`, and only-outgoing → `null` (**RF4**);
    - `[in 1@t1, out 2@t2, in 3@t3, in 4@t4]` → `t3`;
    - with `handled = 4` → `null`, and after a new `in 5@t5` → `t5`.
  - `currentLevel("low", 12h - 1ms)` → low; at `12h` → `{ level: "normal", movedFrom: "low" }`; at `15h` → `{ level: "high", movedFrom: "low" }` (**RF3**). `currentLevel("normal", 3h)` → high; `currentLevel("high", 100h)` → high with `movedFrom: null`.
  - Custom `{ normal: 60, low: 360 }`: low at 6 h → normal.
  - `waitingOrder`:
    - a High chat waiting 5 min comes before a Normal chat waiting 2 h;
    - a Normal chat waiting 4 h (now High) comes before a High chat waiting 1 h;
    - chats with `since: null` are dropped;
    - ties go by name.
  - `formatWait(90e3)` → `"2 min"` (rounded up, minimum `"1 min"`), `formatWait(5 * 3600e3)` → `"5 h"`, `formatWait(49 * 3600e3)` → `"2 days"`.
